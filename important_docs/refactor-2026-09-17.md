# Refactor for GitHub publication (2026-09-17)

Applies to: all of `src/**`, `default.project.json`, `AGENTS.md`, `README.md`.
Based on two external AI reviews (recommendation.docx) plus verification
against the actual code and a full Studio playtest.

## What was done

1. **`_G` removed.** `_G.PlayerSkinColors` → `PlayerDataManager` (SSS
   ModuleScript, strict); `_G.ReplayCharacterIdle` → `AnimationController`
   (SSS ModuleScript, strict). Consumers: InventoryServer, MaleFemale,
   ReplaceAvatarWithRig.
2. **Duplication removed.**
   - Color palettes + `getPleasantColor` were copied in InventoryServer
     and InventoryController → single `ReplicatedStorage.ColorPalettes`.
   - Body-part name lists existed 3× (InventoryServer ×2 with dead R6
     names like "Left Arm", MaleFemale ×1) → `ServerScriptService.RigParts`
     (`SKIN_PART_NAMES`, R15-only; hands/feet deliberately excluded —
     they were never repainted).
   - Element config (names+colors) existed in both ElementMenu and
     HoverBorder2 → `ElementMenu.ELEMENTS` (typed `ElementConfig`);
     HoverBorder2 builds its lookup from it.
   - The three byte-identical `HoverEffect` LocalScripts in
     `MainMenuGui/MainContainer/Slot1–3` → one `SlotHover` LocalScript in
     `MainContainer` (deleted the three in Studio).
3. **ColorPicker sliders rewritten**: `while holding … RenderStepped:Wait()`
   polling → `UserInputService.InputChanged/InputEnded` (updates only on
   movement; release outside the slider no longer sticks; division by
   zero guarded).
4. **ElementMenu `findButton` recursion** → `FindFirstChild(name, true)`
   + `IsA("GuiButton")` check.
5. **InventoryController**: long `WaitForChild` chains → `waitForPath`
   helper; 8 equip-label chains → one `equipLabel` helper; typed `InitDeps`.
6. **`CameraLockScript` brought under Rojo** (`src/StarterGui/MainMenuGui/`)
   with the LIVE Studio values (camera Y 4, lookAt (0,8,-50)) — the old
   snippet had Y 8. The divergence caveat in AGENTS.md is obsolete.
   Rejected the reviewers' suggestion to re-assert the camera CFrame
   every RenderStepped: SceneEffects/SceneTransition own the camera
   during transitions and a permanent lock would fight them.
7. **Typing**: `--!strict` on the four new small modules; annotations
   elsewhere (SceneTransition, ColorPicker, HoverBorder2). Full strict on
   the big GUI scripts was deliberately skipped — no offline analyzer in
   this environment to verify cleanliness.
8. RotateScript dedented (was indented by 4 spaces) + header; stale
   `.txt` references in headers/warns updated to repo paths.
9. `README.md` (GitHub-facing) added; AGENTS.md updated; `snippets/`
   removed (HoverEffect drafts + stale CameraLockScript).

## Reviewer claims that were wrong or already fixed

- `:Remove()` in InventoryServer — no such call; it already used
  `:Destroy()`.
- `wait()` in SceneEffects (deprecated) — the file already uses
  `task.*` everywhere.

## Verification

- `rojo build` passes; all Studio script sources hash-matched to repo
  files (modulo blank lines: the Studio MCP `multi_edit` tool strips
  blank lines — `execute_luau` + `.Source` is byte-exact; a plain Rojo
  connect re-asserts repo formatting anyway).
- Full Studio playtest through: spawn + random outfit, idle replays,
  loading screen → menu → editor, gender swap, inventory open, palette +
  ColorPicker drag, element select → Play → final transition → server
  teleport request. Zero errors.
- Playtest caught two transcription/renaming bugs before they shipped:
  invalid type syntax `(()) -> ()` in ColorPicker, and `config.Name`
  (capital N) left in HoverBorder2's PlayButton handler after the
  `ELEMENTS` field rename to `name` — the element fired as nil and the
  server whitelist rejected it.
